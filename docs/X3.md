# X3: higher-resolution composition and PatchCore (EXPLORATORY, MVTec LOCO)

**Status: EXPLORATORY.** X3 was designed after the confirmatory MVTec LOCO evaluation of the pre-registered suite
(`runs/PREREGISTRATION.json`, v2) had been seen. Its numbers are measured on the same test split that motivated it, are
optimistically biased, and cannot be confirmed without fresh labelled data, which does not exist here. The confirmatory
LOCO result remains the pre-registered full model G_full (`docs/RESULTS.md`). All metrics here are AUROC-based.

## Motivation (2026-09-26 ~13:25 local)
After the confirmatory LOCO results, the project owner asked for better MVTec LOCO detection. Normal images showed
a likely cause of the weak categories: pushpins pins (and screw_bag parts) are smaller than one 14-px DINOv2 token at
the 448-px letterbox, so part-level evidence is not resolved.

## Specification (written 2026-09-26 ~13:30, BEFORE X3 was built or evaluated)
New components live in `src/hybridad_x/`. They are fitted on LOCO fit images only and normalized on validation
normals only:
* `composition_hr` (`src/hybridad_x/composition_hr.py`): the Part-Occupancy Composition Memory at an 896-px letterbox
  (64x64 token grid), with the same K = 10, PCA-64, tau 0.05, kNN 3 and 4x4 layout grid (disabled for screw_bag, as in
  the pre-registered branch), PLUS count evidence: connected components (>= 3 cells) of each visual cluster's hard map.
  Counts are enabled per cluster ONLY if, on the normal FIT images, that cluster's count equals its modal value (>= 1)
  in at least 90 % of images ("instance separation justified on normal data"). Clusters failing the rule get no count
  evidence; if none pass, counts are off.
* `patchcore_hr` (`src/hybridad_x/patchcore_hr.py`): a separately named PatchCore variant (the protected branch is
  untouched) at a 512-px letterbox (64x64 layer2 grid), coreset 1 % (the author's IM320 setting), k = 1, max
  aggregation, padding excluded.
* Fused model X3 = protected PatchCore + patchcore_hr + local student-teacher + DINOv2 reconstruction + composition_hr.
* Pre-specified fusion: MEAN (`X3_mean`, primary) and MAX (`X3_max`, secondary). Mean was chosen as primary because it
  was the better pre-registered fusion ablation on LOCO, a preference formed after the test results were seen and
  stated openly here.
* Branch scores are standardized with normalizers fitted on each category's held-out validation normals, as in the
  pipeline. No test image or label is used to fit or normalize anything.
* Configs: `configs/exploratory/experiments/X3_mean.yaml`, `X3_max.yaml`; runner: `scripts/x3_run.py`
  (`prepare`, then `evaluate`, which labels every output EXPLORATORY).

## Test evaluations of X3 (disclosure)
The X3 test evaluation (`scripts/x3_run.py evaluate`) was executed twice on 2026-09-26: at 13:55-13:56 and again at
13:59-14:00 local (two entries each for X3_mean and X3_max in `runs/TEST_ACCESS_LOG_excerpt.jsonl`, and likewise
in `runs/exploratory/TEST_ACCESS_LOG_excerpt.jsonl`). All X3 code and configs were last modified at 13:16 and all X3
calibrations were written before 13:55, so both executions used identical code and scores, and they printed identical
results. Nothing was changed between or after them. The reason for the second execution is not recorded.

## Reading
* X3_mean raises macro AUROC from 0.860 (G_full) to 0.885, mostly through structural
  anomalies (structural AUROC 0.912 -> 0.947) and breakfast_box
  (0.874 -> 0.923).
* Logical anomalies remain the bottleneck: logical AUROC 0.828 -> 0.844;
  pushpins 0.713 and screw_bag 0.673.
* Because X3 was designed after the test results were seen, none of this is confirmatory.
